# d-obs 架构评审（含评分）

- **场景**：risk-quality-reviewer
- **评审问题**：d-obs 是否足以胜任「D-Robotics 生产环境独立可观测平台」的定位？
- **评审目标/容差**：内部生产平台的可用性与安全底线优先于横向扩展；接受单机部署的形态，但不接受「平台自身死亡无告警」
- **日期**：2026-09-20，代码基线 main @ 9a6d74c
- **证据**：`d-obs.evidence.md`（架构事实）+ 本文新增定量证据

## 总评分：4.1 / 5（约 82/100）

对定位为「内部生产可观测平台」的系统，这是**显著高于平均线**的分数。边界/安全/可运维是强项；扣分集中在**部署形态（单机共域）**与**前端层可维护性**，而非设计能力。

## 结论

d-obs 的**设计纪律**（fail-closed、契约边界、无裸执行、已实测的状态机）和**工程过程**（带回滚的发布、无库冒烟、配置巡检）对 30 天年龄的项目而言异常成熟，4.1 分主要反映了这一点。它当前最大的暴露面不在代码里，而在**部署形态**：一台主机同时是被观测对象、观测者、和告警者。P0 两项（外部看门狗 + 备份演练）成本极低，做完后该平台对定位的匹配度可到 4.4+。

## 评审局限性

- 未做逐文件安全审计（XSS/注入路径为抽查非穷举）；F5 表述为待验证项而非漏洞
- 运行时行为未实测（未连生产库/未压测）；评分基于代码、配置、测试与文档证据
- 依赖 CVE 未扫描（本机网络受限，npm audit 未执行）
