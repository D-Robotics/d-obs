# 告警来源与历史证据

告警卡片与可观测中心使用同一份发生时证据。业务告警按 SSO 账号、应用版本、
客户端形态与功能模块分组；没有采集的字段显示“未上报”。只有明确的基础设施
规则才显示这些维度“不适用”。模块优先使用明确埋点，已知工具可映射至对应能力，
其他情况保留组件标识，不推断用户当时打开的页面。

卡片展示前 4 组来源，详情最多展示 8 组和 20 条原始失败记录样本。总数在截断前
计算；分组与样本不足以覆盖全部来源时，页面明确说明。失败调用次数、合并上报的
异常次数、存储记录条数与独立 Run 数分别计算，不能互相代替。工具告警继续按失败
调用次数触发，同一 Run 多次失败也会告警。

通知前保存有界白名单快照，保留 35 天，不包含对话正文、工具参数、完整错误日志或
凭据。恢复通知保留最近故障窗口的证据。快照保存失败时卡片仍提供核心事实，并明确
提示历史证据未保存，不生成承诺历史详情的时间链接。

新通知链接使用 `#alert=<key>&at=<ISO timestamp>`，详情读取与通知一致的发生时快照。
即使当前检查健康、事故已恢复或滚动窗口移走，仍可读取保留期内的快照。旧链接不带
时间时查询该规则最新快照；缺失的历史快照不会自动替换成其他时间的记录。

历史窗口可依据仍保留的原始记录显式回溯生成。此类证据标记为
`historical-reconstruction`，展示实际保存时间，不能把补存解释为当时已有快照。

受保护接口为 `GET /api/ops/observability/alerts/:alertKey/evidence?at=<ISO timestamp>`。
账号、版本与 Run 标识不进入跳转 URL。管理员与租户请求继续使用既有鉴权链路，租户
只能读取自身快照。原事件详情下钻沿用既有平台权限，租户页面不会提供无权访问的按钮。

告警中心按最近活动或恢复时间筛选历史事故，并始终保留进行中事故。重开已恢复的事故
时重设首次发生时间；持续中的事故保持原时间和负责人。
