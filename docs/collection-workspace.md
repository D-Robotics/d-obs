# 统一采集工作区

主控制台 `ops-observability#collection/tasks` 将现有云端与终端采集组织为同一工作区。`#data/assets`、`#data/datasets`、`#data/loops` 使用同一导航、登录身份和主题；原 `data-center#loops` 等链接迁移到对应主控制台视图。

## 使用已有采集

- 云日志桥：复用已有 journald、Docker、文件来源。可配置轮询间隔、发送间隔、批量与队列容量。保存产生期望版本，采集进程重新加载并返回匹配的实际应用版本后才标记生效。
- OTLP：在工作区查看凭据接收状态，进入原接入凭据、日志、指标与链路模块配置和查询。持续接收模式没有“启动远程采集”的虚假按钮。
- 设备心跳：选择已登记设备下发 5–3600 秒采集间隔。`pending/delivered` 表示等待，设备 `ok` 回执才代表配置生效。
- SSH/RDK：选择服务端已配置目标、日志来源、模板、历史行数和时长，实际启动原采集驱动；旧会话可纳入运行与产物归档。旧会话未记录的参数只用于新流程模板。
- 文件接收、视觉实验、外部探针与业务拨测：保留原接入和执行能力，在统一工作区进入参数配置、实际接收记录、实验导入和检查回执。

## 流程版本和运行

流程为 `采集源 → 可选文本关键词过滤 → 最小字节质量检查 → 资产归档`。点击流程节点编辑模块参数。修改配置生成不可变的新版本；启动选择明确版本，运行记录绑定该版本和实际上游会话。

顶部“刷新数据”和工作区刷新均读取当前账号最新记录。任务与来源页的持续接收状态每15秒更新，运行中流程与待确认配置每4秒更新。正在编辑表单、打开配置对话框或执行请求时暂停自动更新，保留未保存草稿；离开工作区或身份重置后取消轮询，权限失效后等待重新登录。

过滤只支持有界 UTF-8 文本的纯文本关键词，不支持任意正则、命令或地址。过滤后的内容与原始内容分别归档。质量检查失败不会伪装为成功结果。成功归档绑定真实 SHA256、字节数和可选固定数据集；重新归档不重新执行采集，内容变化拒绝静默覆盖。

执行回执丢失显示中断/未知，不自动重新启动。重启后只检查已有会话并完成已授权归档；从未取得上游身份的运行不会恢复执行。采集状态、归档状态、设备应用状态与改善效果验收分别表示。

## 权限与持久化

新接口位于 `/api/ops/observability/collection-workspace`，保留运营权限、稳定 SSO ID 归属、变更意图 guard、严格参数和只读拒绝。浏览器只选公开目标/来源 ID；连接地址、密钥、原始源路径和接收秘密不进入模块配置。

流程元数据默认保存到 `RDK_DATA_CENTER_STATE_DIR/collection-workspace`，可通过 `RDK_COLLECTION_WORKSPACE_STATE_DIR` 改变。云日志桥配置默认 `/var/lib/d-obs-log-bridge/collection-config.json`，daemon 回执为同目录 `collection-status.json`。文件使用私有权限、原子更新和完整性检查。

数据中心备份固定先锁采集元数据、再锁资产，包含流程版本、运行记录、固定快照与真实文件。恢复后采集上传 token 失效，须重新签发。恢复不会自动重新开始未知设备采集。

没有服务端 SSH/RDK 目标或匹配 Vision SDK adapter 时明确显示不可用。隔离 fixture 验收只能证明执行与归档链路，不代表生产设备已连接或质量改善已完成。
