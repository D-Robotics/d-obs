# RDK Camera AI · 产品说明

**名称**：rdk-camera-workshop（RDK Camera AI）· 版本 1.2.0 · 作者 D-Robotics
**一句话定位**：在 RDK Studio 或兼容 MCP 宿主中，用自然语言完成相机点亮、有界 ISP 调参、客观测量、恢复与交付的 AI 执行与测量系统——每一步有回执、可复现、可审计。

## 1. 解决什么问题

相机调试长期依赖资深工程师：查规格、配模式、开流、试参、对比、恢复，一轮下来以小时计，且试错过程不可追溯。本插件把这条链组织为 49 个原子工具，由 AI 在**显式授权与硬边界内**执行：

- 工程师说目标（「画面偏红，改善肤色」），AI 执行有界调整并给出前后客观对照；
- 每次写入前有资格检查，写入后有独立回读，随时可恢复原始配置；
- 全程哈希留痕，调参结果可导出、可复载、可交付。

适配硬件：RDK X5 + Sony IMX415（3840×2160 MIPI，已实机验证）；USB/UVC 相机走通用控制路径。

## 2. 能力总览（五个能力域）

| 域 | 能力 |
| --- | --- |
| 连接与诊断 | 连接状态自检（含修复提示）、能力目录、运行时状态、`doctor` 命令行探活与批量核验 |
| 点亮与采流 | 探测、管线校验、点亮、预览启停、取帧、抓帧——全部要求真实新帧才报告「出图」 |
| 控制与调参 | 曝光/白平衡/色彩控制读写、**有界 AI 调参 Run**（探索轮数 1–6 显式声明）、原生 ISP 快照读写与按 ID 复载 |
| 测量与验收 | 前后帧对照分析、32 桶亮度直方图 + RGB 通道分布、白平衡 B/G·R/G 比值、24 色块 ΔE76 评估、验收计划与记录、交付打包 |
| RAW 与标定 | RAW 采集（资格门禁下）、RAW 回灌、BLC/LSC/CCM/AWB 离线标定任务（输入强制真实测量） |

## 3. 具体使用例子（真实回执摘录）

### 例 1 · 三分钟接入自检

安装插件后，配置一次私有连接（仓库外 0600 文件），然后：

```console
$ node mcp/setup.mjs doctor
{"status": "connected", "toolCount": 49, "runtime": "responded",
 "hardware": "unverified", "next": "在宿主中读取 runtime_status，选择实际登记的设备；连接成功不代表相机已点亮。"}
```

退出码 0 即配置与服务均可用。30 个工位批量核验时按退出码逐台收集，失败台的 stderr JSON 自带错误码与修复建议。对话里出问题时，AI 调 `vision_connection_status` 会拿到人话提示而非裸错误码（例如「认证失效，请在原服务更新凭据后重试」）。

### 例 2 · 自然语言点亮

> 用户：「点亮我的相机并保存原始状态。」

AI 依次调用探测 → 管线校验 → 点亮 → 启动预览 → 取新帧，随后保存完整原始配置作为可恢复版本。内核与 SDK 回执逐层核对：真实新帧有 SDK 时间戳与图像哈希，开流失败会如实报错而非假装出图。

### 例 3 · 有界 AI 调参（带探索预算）

> 用户：「观察文字明暗，做有限调整并给我前后对照。」

AI 提交调参 Run 时显式声明探索预算（`maxRounds`，1–6，课堂/限时场景通常 1–2）。每轮：模型看当前帧与统计 → 给出有界参数补丁 → 执行器应用 → **独立回读**确认写入 → 采新帧 → 前后直方图对照。轮数用尽或模型判断无改善即恢复原始配置——「无改善保留原值」是有效结论，不是失败。

### 例 4 · 白平衡比值对照（2026-10-23 真机实录）

演练工具在真机采得基线帧后自动输出：

```json
{"A1": {"paperPixels": 3179684, "BoverGMedian": 0.99333,
        "RoverGMedian": 1.23973, "clippedAt255Fraction": 0.0, "usable": true}}
```

解读：画面白面充足、**红偏高 24%**（偏暖红），与目视一致——多光源场景下自动白平衡压不住，正是手动 WB 的用武之地。方向确定后有界调整红增益，比值应向 1.0 回归；恢复后复核回落（漂移阈值 0.02）。历史受控试验的完整正例：B/G 1.178 → 1.024，恢复后回升，两次独立重载一致，2026-10-22 已用本插件工具链对归档帧复算验证。

### 例 5 · 复现与交付

> 用户：「重新加载我选定的参数」「导出我的 tuning 和调优手册。」

调参结果导出为效果库文件，**按归档 ID 复载**（服务端重读文件并校验哈希，不依赖模型转述），加载后再采新帧核对。交付 ZIP 内含 delivery.json、调优手册、实际图像与版本证据（R9 实测：手册 46 KB Markdown、包 17 条目 CRC 校验通过）。

### 例 6 · 同一相机跑 BPU

> 用户：「用这台相机跑检测示例。」

预览切 `bpu-detection` 模式，帧送板端 BPU 推理，回执含检测数、SDK 时间戳与帧哈希。运行成功与检测出目标是两件事，回执分开陈述。

### 例 7 · 课堂验收记录

验收计划（场景、照明、必验项、阈值）先保存；验收记录只录入**操作者实际提供的**观察或测量，绑定图像与参数哈希。模型判断、统计输出与人工评分分别标注，不互相冒充。

## 4. 诚实的边界

1. **不承诺「任意场景调好画质」**——有界调参闭环已实机验证，但画质正例依赖受控场景（测试卡+固定照明）；多光源复杂场景的白平衡校正仍在能力建设路线上。
2. **参数写入受证据治理**——写授权需要配置私有读回证据（modeReadbackEvidence），未配置时控制面只读。这是防误写的设计，不是缺陷。
3. **Bayer RAW 实采未开放**——SDK 读回资格未闭合，相关能力（回灌、RAW 级对照）在资格闭合前不启用、不宣传。
4. **不做自动搜索与多模块联调**——现状是 AI 有界试参（每轮最多三个已授权数值叶子），不是一键全模块优化。
5. **模型训练依赖外部平台**（RoboGO），本插件负责相机链路；**远程/云形态**需要 Studio 宿主侧配套。
6. **新 sensor 适配**不是自动的——需要资料核对、驱动开发与实机验证后才有原子能力。

## 5. 质量与验证状态

- **测试**：连接器 31 项（含对抗性用例：路径泄漏、权限、超限、注入）、白平衡演练 15 项单测 + 1 项编排级端到端、打包器 8 项；连接器对真实服务做过三路径黑盒端到端（连接/往返/失败契约）。
- **实机**：RDK X5 + IMX415 单套全链真机验证（点亮→调参→恢复→复载→BPU→交付→收尾）；白平衡演练工具真机出数（2026-10-23）。
- **发行状态**：内部候选（`releaseQualified:false`），正式课堂发行与来源审计进行中；Studio 原生连接当前仅支持本机模式。

## 6. 快速开始

1. 在 Studio 插件中心安装 rdk-camera-workshop（或手动注册 stdio 连接器）；
2. 配置私有连接：`node mcp/setup.mjs configure --url <服务MCP地址> --auth sso --credential-file <绝对路径凭据文件>`（配置与凭据放插件外，0600 权限）；
3. `node mcp/setup.mjs doctor` 确认 `connected`；
4. 在对话里说「点亮我的相机并保存原始状态」开始。

详细边界、失败恢复与 X5 机制说明见插件 README 与技能参考。
