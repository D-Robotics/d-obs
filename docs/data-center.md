# 云端与终端数据中心

数据中心将真实文件、外部存放位置、采集任务、不可变数据集和改善证据关联到同一个项目与目标。入口是 `/dobs/ops-observability/data-center`，沿用可观测中心的运营访问检查，并按实际账号隔离私有数据。

当前版本接收客户端主动上传的真实文件。创建采集任务不会连接设备、执行远程命令、自动训练模型或下发版本；这些工作的实际产物与回执可以归档为阶段证据。数据中的 `cloud`、`edge` 与 `targetId` 表示任务声明的来源和目标，不能单凭这些字段证明硬件连通性或设备采集真实性。

## 采集客户端接入

网页提供“下载上传客户端”，固定下载地址为 `/dobs/ops-observability/data-center/upload-client.mjs`。脚本只使用 Node.js 内置模块，不携带平台或采集凭据。

1. 在“采集任务”填写项目、来源、目标 ID、类型和预期文件数量。
2. 进入任务的“接入采集客户端”并签发 token。token 仅在签发响应中展示，保存在客户端受控环境变量 `RDK_DATA_COLLECTION_TOKEN` 中。每次重新签发都会立即废止旧 token；任务完成、失败或取消后也会废止 token。当前 token 没有独立到期时间，应及时结束任务或轮换凭据。
3. 云端进程与终端进程使用同一上传协议，token 仅授权该任务接收文件。它不能读取、下载、删除资产，不能改任务状态，也不能向其他任务或项目写入。
4. 核对归档文件数量与内容后，由操作员确认任务完成。首个有效上传将 `planned` 变为 `collecting`，服务不会仅凭收到一个文件自动宣布完成。完成要求实际文件数等于预期数，并重新校验已归档文件的哈希。

凭据已通过秘密管理工具或受控环境注入后，运行：

```bash
node tools/data-center-upload.mjs \
  --origin https://rdkstudio.d-robotics.cc/dobs \
  --task 00000000-0000-4000-8000-000000000001 \
  --file /absolute/path/capture.raw \
  --title '逆光场景原始样本'
```

示例 UUID 须替换成真实任务 ID。CLI 不接受 token 命令行参数，不打印或持久化凭据；成功只输出资产 ID、实际 SHA-256、字节数与 HTTP 状态。远程地址必须使用 HTTPS，HTTP 仅供回环地址上的本机测试。客户端拒绝带账号密码、查询参数、片段、路径穿越的服务地址，也拒绝重定向，以免把采集凭据发送到其他入口。

CLI 读取普通非空文件，拒绝最终符号链接和变化中的文件，计算实际内容哈希后上传。协议为：

```text
POST /dobs/api/data-center/ingest/<task UUID>
Content-Type: application/octet-stream
x-collection-token: <task-scoped token from controlled environment>
x-data-asset: encodeURIComponent(JSON.stringify(metadata))

metadata = {
  filename: 'capture.raw',
  mimeType: 'application/octet-stream',
  sha256: '<64 lowercase hexadecimal characters>',
  title: '逆光场景原始样本'
}

body = 原始文件 bytes
```

服务端从任务补全项目、来源、类型和目标，客户端若提供这些字段则必须完全匹配任务。服务端重新计算哈希；成功返回 `201` 和 `contract: rdk.data-center.v1`、`asset.id`、`asset.sha256`、`asset.sizeBytes`。CLI 再核对回执的哈希与字节数。同任务重复提交相同哈希会复用已有资产，不增加任务计数。

`403` 表示 token 无效、已轮换或采集范围不符；`409` 表示任务状态、文件数或配额不允许写入；`413` 表示大小限制；`422` 表示内容哈希不符。CLI 不自动重试。超时、传输中断、`5xx` 或成功响应中的错误回执都显示“结果未知”，应先在任务和资产目录核对是否已归档，再决定下一步。生产验收不应使用真实设备数据或生产写入来代替本机 fixture 测试。

## 资产治理与数据集

资产可上传实际内容，或登记 `https://`、`s3://`、`gs://` 外部引用。外部 URI 不接受凭据、查询参数或临时签名，服务只校验地址格式，不访问该位置、不声称远端内容已下载或校验。外部资产以 `storage: external` 标识，没有平台计算的内容哈希；已上传内容以 `storage: uploaded` 和真实 SHA-256 标识。

名称、类型、来源、项目、目标、标签与实际采集时间用于检索。未知的采集时间和目标应留空，不能用上传时间冒充采集时间。数据没有自动扫描、脱敏或内容分类能力，接入方应选择获准纳管的文件。

数据集固定同一项目的一组资产及其元数据快照。每个版本最多 300 项；同名同项目再次创建会生成递增版本，已有版本与成员不改写。上传资产创建快照前会再校验内容。被数据集、闭环或已完成任务引用的资产不能直接删除，以保护已有证据关系。外部引用可以进入数据集，但闭环基线和阶段证据要求平台中可读、完整的真实归档内容。

界面导出的公开 manifest 是当前账号的资产、任务、数据集和闭环关系清单，不包括采集 token 或 token 哈希，也不包含文件原始内容。它适合检查 lineage，不能用它独立恢复存储。

## 四阶段改善闭环

创建闭环时固定项目、目标、数据集、真实基线资产、基线版本、指标值及验收方向和最小改善幅度。后续依次提交阶段证据，不能跳过阶段：

| 阶段 | 必需记录 | 状态结果 |
| --- | --- | --- |
| `analysis` | 真实分析证据文件、实际版本、同一目标、说明 | `analyzed` |
| `evaluation` | 真实评测证据文件、与基线不同的候选版本 | `evaluated` |
| `deployment` | 与评测候选版本相同的部署证据及同一目标 | `deployed` |
| `verification` | 独立验收文件、相同候选版本、固定基线值、申报验收值 | `verified` 或 `verification_failed` |

阶段证据必须来自同账号、同项目、同目标，服务每次读取验证文件字节与哈希。验收不允许复用基线内容或已有阶段证据；失败后可用新的独立证据再次验收，通过后的闭环固定。

验收改善幅度按指标原单位计算绝对差值：提高方向为 `candidateValue - baselineValue`，降低方向为 `baselineValue - candidateValue`；改善幅度大于等于预先固定的阈值时通过。基线值须与创建时完全相同。

数值的 `measurementSource` 明确为 `reported`。平台检查文件、来源关系、版本一致性、数值与门槛，不从文件内容自动提取指标，也不证明申报数值来自真机仪器。部署证据提交成功说明证据已保存；`verified` 表示这次申报指标通过所设门槛，不能扩展为自动训练、真实下发或全部场景质量通过。

## 视觉 Workshop 桥接

当前账号可将视觉实验导入数据中心。桥接通过原 Workshop 的受保护字节读取接口重新校验 Raw 和结果图哈希，纳入参数候选及保留原始关系的 provenance 报告，创建不可变数据集。每项导入有 `provenance.system: vision-workshop`、实验 ID、原始制品 ID 和类型；HTTP 上传不能自行声明这些可信桥接字段。

原模块 `runner` 来源保留为终端数据，外部上传保留为云端归档，并在说明与来源报告中保存原模块来源。实际 `apply_tuning` 与回读记录保持原含义。导入返回 `qualityVerification: unverified`；不会把上传、参数应用或回读成功当成实机画质验收。

相同实验快照重复导入复用已有制品和数据集。实验产生新候选、样本或回执时会形成新快照。部分导入失败时已归档资产保留，回执列出已导入 ID；先查询核对，桥接的幂等恢复也不会执行设备动作。

## 配额、持久化与恢复

服务默认状态目录为 `~/.local/state/d-obs/data-center`，生产通过专用 `RDK_DATA_CENTER_STATE_DIR` 指向受控持久目录。状态目录和 blobs 目录权限为 `0700`，manifest 与内容为 `0600`。服务使用跨进程锁、内容哈希、临时 manifest 原子替换和文件/目录同步；损坏 manifest 或文件会明确失败，不能静默退回空库。每个服务实例应使用同一受控本机状态目录，当前实现不提供多机共享状态或分布式写入。

默认限额是同一状态目录全部账号合计：

| 项目 | 默认限额 |
| --- | --- |
| 单文件 | 64 MiB，必须非空 |
| 已上传内容 | 2 GiB |
| 资产数 | 2,000 |
| 采集任务数 | 500 |
| 数据集数 | 500 |
| 闭环数 | 500 |
| 单任务预期文件数 | 1–1,000 |
| 单数据集成员数 | 1–300 |
| 单闭环阶段证据数 | 64 |
| 全部元数据 manifest | 32 MiB |

实际能力接口中的 `quota` 为当前服务限额。配额耗尽会拒绝新写入，不覆盖旧资产。反向代理须针对 `/dobs/api/data-center/ingest/` 与受保护的资产上传路由允许所需大小；普通平台入口的较小限制保持原值。代理返回 `413` 时应同时核对能力目录和代理配置，不能把后端 64 MiB 能力当成公网已允许该大小的证明。

内部运维可通过 `DataCenterService.backupState(<新的私有备份目录>)` 在相同状态锁下导出一致的 manifest 和所有已校验 blobs。备份保留完整恢复所需的私有状态及账号哈希，但主动清除采集 token 哈希；线上 token 不受备份影响。备份应按私有资料管理；不得放入公开 manifest、发布 tar、Git 或聊天。备份目录必须为新目录并位于当前状态目录之外，不能覆盖已有备份。

恢复应在服务停止写入时进行：保留当前状态目录作为恢复点，将可信完整备份复制到新私有目录，核对 manifest 校验值、逐文件内容哈希、数量与权限，再通过本任务专用环境配置调整 `RDK_DATA_CENTER_STATE_DIR` 指向新目录并启动服务。核对真实状态与受保护目录后再恢复接入；有疑问时回到原目录。不要只复制公开 manifest，不要将备份并入在线目录，也不要修改其他服务或共享环境文件。恢复后的所有旧采集 token 均无效，所有未完成任务必须重新签发凭据；这可防止旧备份复活已撤销的 token。

本机客户端回归：`node --test tools/data-center-upload.test.mjs`。使用本机 HTTP 服务和临时文件 fixture 验证真实字节、哈希、凭据范围、大小边界、HTTP 失败、重定向和未知结果；这些测试不会向生产上传，也不能代替生产健康、权限及公网接线验收。

生产为文件状态设置独立的 `d-obs-data-center-backup.timer`，每小时调用 `tools/data-center-backup.mjs` 在服务同一跨进程锁下备份；默认目录 `/var/backups/d-obs-data-center`，保留最近 24 份一致快照。`RDK_DATA_CENTER_BACKUP_DIR` 和 `RDK_DATA_CENTER_BACKUP_KEEP` 可设置专用备份策略。此文件备份独立于已有 PostgreSQL 备份；本机快照不能代替异机灾备。恢复演练须核对真实文件、固定数据集和 token 全部失效。
