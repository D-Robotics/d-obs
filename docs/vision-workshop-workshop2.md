# Workshop 2：从相机工程调试到测试交付

适用对象是商业客户工程师与测试人员。平台和 Studio 插件负责保留实验、工具回执、图像、配置和交付证据；现场活动以指定硬件和已确认的软件版本为边界。主办方课前准备并验收相机环境，课堂不把首次驱动适配当作已经具备的条件。

## 课前准备与进入条件

主办方先确认板卡、模组批次、镜头、排线和供电，固定实际 OS、驱动/相机包、SDK、原生库构建版本和 Sensor 模式。登记宽高、帧率、Bayer、位深、packing、stride、CSI 配置及基础效果库版本；按对应模组资料核对，不套用其他环境的最低版本或接线结论。

课前完成一次冷启动点亮、真实新帧归档、受控参数写入/回读、恢复回读和成果导出。确认账号权限、设备分配和所用 Studio Runtime；正常对话仍须满足该部署实际的板卡准入条件。资料检索与无设备文件实验可先进行，但不把这类练习写成实机验证。

准备可辨认的固定测试场景、合适照明、灰卡/色卡或实际需要的测量工具、同场景基线素材以及明确标为合成数据的离线备用练习。RAW 来源、采集条件与测量条件必须真实记录。SDK 模式 getter、字段范围和标定映射没有资格证据时，对应项保持不可用。

建议由工程操作员执行，测试人员复核，主办方工程师处理环境问题，客户代表确认场景和交付范围。事先约定一项可完成的调优目标、测试方法、阈值、样本与责任人；不要在课末依据结果临时降低阈值。

## 225 分钟可裁剪安排

225 分钟为 3 小时 45 分钟，适用于课前设备已预验收的活动。未完成预验收、出现驱动/SDK 适配缺口或硬件问题时，暂停对应实机环节，或转入明确标注的离线教学；不承诺仍按原时间完成点亮、调优和质量验收。

| 时间 | 环节 | 阶段出口 |
| --- | --- | --- |
| 0–15 分钟 | 目标与验收约定 | 实际场景、问题、评价方法、阈值、负责人 |
| 15–40 分钟 | 环境与版本预检 | 设备、接线、软件版本、模式、授权和恢复条件 |
| 40–70 分钟 | 点亮与稳定出图 | 真实探测、链路与点亮回执，可辨认的新帧 |
| 70–100 分钟 | 采图与原始基线 | 原始配置、RAW/视频帧来源、场景条件与哈希 |
| 100–160 分钟 | 受控调优与比较 | 有限参数变化、独立回读、新图和退化记录 |
| 160–195 分钟 | 工程到测试评估 | 约定方法下逐项结果、未知和失败项 |
| 195–225 分钟 | 恢复、复现与签收 | 最终设备状态、复现步骤、交付包和补测责任 |

可以减少已通过预检的重复演示，收窄为一个场景和一个目标，把复杂标定或其他模式移至课后。不要省略原始基线、独立回读、恢复、来源校验与签收边界来赶进度。

## 现场执行

1. 创建归属正确账号的实验，登记设备、SDK、接口和模式；录入验收计划与约定范围。没有适配器时保存资料与文件实验。
2. 读取实际能力，执行 `probe`、`pipeline_validate`，再使用已适配驱动 `bringup`。设备树、新驱动、寄存器初始化和 SDK 构建属于另行工程接入；I²C 有地址不代表出图。
3. 启动预览并归档新帧，检查可辨认的场景、尺寸、时间和连续性。保存原始控制、效果库来源、参数快照及恢复版本。读 readiness 是查看存量记录，不能代替本次探测。
4. 采集或导入 RAW，核对 Bayer、位深、packing、stride、字节数与 SHA-256；PNG/JPEG 是处理后图像，不能作为 Bayer RAW。记录照明、距离、焦点、曝光、增益和自动模式。
5. 仅调整适配器支持、有范围且有回读资格的字段。手动项 inactive 时先确认相应模式；模式无资格时不写。每轮先保存理由和输入，再核对实际回读和新采图，不为旧队列帧重标候选版本。
6. 支持回灌时用同一 RAW 和同一基础版本比较 ISP 输出；否则固定取景与照明，并标明运动、AE/AWB 等混杂因素。分别观察曝光、暗部噪点、彩噪、雾感、颜色和边缘/纹理退化。
7. 测试人员按预先约定的条件复测。PNG ROI 的亮度、通道均值和近黑/近白比例是输出码值观察；亮度标准差不能当作 SNR。人工评分、AI `goalSatisfied`、离线标定成功和回读一致均不自动代表画质合格。校准 SNR、MTF、色差及动态稳定性需要适当测量与测试流程。
8. 确认最终保留哪一版，恢复原始状态或应用约定版本后重新回读并归档终态图。在约定环境独立复现，停止本组启动的预览，完成交付检查。

## 故障与未知状态

缺驱动、库、权限或模式时停在预检；黑屏、错色、无新帧和链路失败时保留日志、真实检查项与元数据。不要盲扫 I²C 或写寄存器，不使用示例图冒充采图。

写入超时、断连、帧哈希不符或回读不符时，先查看实验设备账本与实际状态；结果未确认不自动重放。恢复失败须保留 `unconfirmed`，停止新调参并由负责人处理，不能猜原值或仅凭模型文字声称已恢复。

当参数减少高光却增加噪点或损失细节时，保留退化证据，恢复已验证基线并重新回读/采图。时间不足时交付已完成内容及未完成清单，明确补测负责人和日期。

## 交付文件的角色

| 交付项 | 实际作用与限制 |
| --- | --- |
| `manifest.json`、原始基线与版本记录 | 追溯资产、配置、设备操作和恢复版本；不是新调优效果库 |
| `candidate_tuning.json` | 选定候选的适配器配置。格式、SDK、Sensor 模式与回读条件必须匹配 |
| `ai-debug/<runId>/` | 原始与曾推荐参数、模型判断、图像与回读报告；best 配置可能已经恢复而未保留在设备上 |
| SDK 效果库归档 | 原 SDK 输入字节及哈希，配合公开模块回读；不自动包含后续全部模块修改，也不证明未公开字段全值读回 |
| `vendorCandidate` 厂商效果库候选 | 仅在可信 SDK/profile/layout、模板、原始模块基线与全部变更映射齐备时生成，角色为 `vendor_effect_library_candidate`；`blocked` 不返回候选字节，生成成功仍为 `generated_requires_target_validation` |
| `vendor-tuning/<id>.json` | 实验实际归档的候选原字节，保留文件哈希、字节数、映射绑定与导出配置哈希；显式选择交付目标后按该版本验收，归档成功本身不代表装载成功 |
| native 模块候选及 `snapshotId` | 可依赖适配器私有快照、ABI/layout 和软件版本；不能直接当成通用厂商效果库 |
| 可独立部署候选 | 仅按实际支持的部署格式和已包含的依赖交付；需列出版本、格式与哈希，并完成独立加载、回读、恢复和约定场景复测。没有这些证据时保留待验证 |
| `calibration/` | 标定任务和已校验原始结果字节、哈希；SDK 中立计算需匹配私有映射才能实际应用，不能当作量产 tuning binary 或质量证书 |
| `handbook.md`、`delivery.json` | 本次操作指南、真实记录及验收/交付状态；保留未知、未执行、失败与限制 |

完整 MIPI 厂商效果库、普通参数候选和实验元数据是不同交付物。平台导出元数据不会自动生成完整可移植库；也不能把归档的原效果库当成包含本轮所有修改的新库。私有快照/依赖由授权工程人员按交付格式管理，不能把令牌、SSH 凭据或模型密钥塞入共享手册与 ZIP。

厂商候选库通过显式 `tuning_load` 提交 `artifactRole`，服务先验证私有生成回执，实际 SDK 加载后独立读取模块并获取新帧。`target_reload_recorded` 表示已记录这次加载，不直接表示可独立交付；还要核对真实原生来源、`freshSessionObserved`、模式资格、恢复和约定场景画质。合成后端换实例不算新原生会话；同会话加载和旧版无角色加载也不能补授独立候选证明。原效果库归档的角色保持 `sdk_configuration_with_archived_declared_library`、`independentlyDeployable: false`。

验收计划和验收记录按实验归属保存；`delivery.json` 汇总当前选定配置、计划、匹配记录及历史记录。记录必须引用本实验已归档的图像和参数版本。更新计划、场景、输入或配置后重新测试，不沿用旧通过结论；操作者录入的测量值仍标为真实性待核验，不能替代校准报告或独立验收。

图像与配置的最小关联为：实验、设备/模式、场景条件、原始 RAW ID/哈希、基线与候选 ID/哈希、结果图 ID/哈希及实际回读证据。测试人员确认比较输入相同或已明确说明混杂因素；只凭相同尺寸、相近时间或 PNG 统计无法补齐这些关联。

## 最终签收清单

交付状态区分未配置、待记录、场景不匹配、记录失败、必测项不完整与操作者记录满足。厂商目标另区分未装载、目标装载已记录和匹配原生新会话装载已记录。`workshopReady` 仅在当前规则要求的点亮、真实归档候选、匹配装载/新帧、当前计划验收、原始状态恢复和恢复栅栏证据全部齐备时成立，规则范围是 `project_recorded_acceptance_and_target_reload`；该投影不把硬件或画质独立认证从 `unverified` 改成通过。

- [ ] 设备、镜头/模组、版本、模式和场景条件齐全，与实际操作一致。
- [ ] 原始与候选图像、配置、版本和 SHA-256 可关联；外部导入与板端采集已区分。
- [ ] 最终参数实际加载且独立回读，设备最终状态和恢复路径已确认。
- [ ] 按验收计划逐项记录方法、实测值和结论；未测、失败与不适用项有理由。
- [ ] 曝光、颜色、噪点/彩噪、细节、运动、帧率与稳定性按约定范围复测。
- [ ] 交付项明确属于候选、归档库或独立部署产物；接收方核对依赖、格式、适用版本与哈希。
- [ ] 手册、`delivery.json`、约定样本、原始配置和恢复记录已交接。
- [ ] 工程、测试和客户确认人、日期、剩余问题、补测责任已填写。

清单由实际责任人填写，不随文件生成自动勾选。只有真实验收计划、记录和设备证据满足约定范围时，才签收该范围；一次 Workshop 产出不自动扩大到其他镜头、模式、光照、场景或量产环境。
