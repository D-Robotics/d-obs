# 点亮与 ISP 的现场经验

来源：用户于 2026-10-15 在本会话提供的团队经验。用来指导验证顺序与排障，
其中历史版本、供货和效果案例尚未在本任务独立复核；不将它们转成当前设备成功回执或自动执行命令。

## 将经验同步到用户插件

需要让插件用户复用经验时，同时更新产品技能与其包内引用、平台知识的 `teamExperience`、插件中心的数据源/面板和助手指引。
结构化内容源为 `server/monitoring/vision-workshop-field-experience.ts`；保留 `user_reported` 和未独立复核标识，
不要将经验放入已核对的官方 facts，或修改设备 operations、admission 与画质状态。
产品技能的现场指引位于 `plugins/rdk-camera-workshop/skills/rdk-camera-workshop/references/bringup-and-isp-field-playbook.md`。

同步插件 manifest、产品 Skill 和平台声明版本后，使用 `tools/package-camera-workshop.mts` 生成新包。
检查 ZIP 同时包含产品技能引用、独立 `knowledge/camera-field-experience.json` 和知识详情中的同一经验内容，
核对 SOURCE-MANIFEST 中的实际字节哈希；不要只更新仓库内操作员 Skill 就宣布用户插件已更新。
回归检索、受保护的 HTTP/MCP、插件数据源和浏览器经验来源展示；知识读取不得触发硬件或创建实验。
2026-10-15 的本地软件/打包验收见 `.codex/artifacts/camera-plugin-experience-20261015/`，不代表插件已安装或生产已发布。

## 按交付目标推进

1. USB 最小闭环：连接实际相机、采集新帧、识别可辨认的场景/目标、指出有图像依据的画质问题。
   分别记录采集、识别与问题发现；不能用“有预览”代替全部通过。模型或识别程序按任务需要选择。
2. Studio 真实 MIPI 点亮：记录板卡、模组、实际模式与软件版本，在 Studio 完成启动和连续取帧，
   保存可辨认的新帧、日志与真实检查结果。软件 fixture、已登记适配器、USB 成功都不替代这一证据。
3. ISP：先读取匹配 SDK 的 Tuning guide、真实基础效果库和可用参数，再基于本轮画面调整、回读和采图。
   对暗部噪点、彩噪、雾感、颜色及目标细节逐项比较，记录改善和退化。
4. 对外推广：内部先完成对应设备、场景及功能的实机验收，再按用户授权发布工具与资料。
   不把“接口已实现”“能出图”和“ISP 画质通过”合为一个成功状态，也不默认获得上线或分享权限。

## 将专家流程转成可重放操作

团队反馈 bringup 前置工作原由蔡兴顺手工处理。复现时记录实际输入资料、接线与版本前提、
操作步骤、配置差异、编译部署产物、失败信号及成功证据，再将已经跑通的步骤补入适配器与技能。
未拿到实际步骤时列为待采集，不根据“专家做过”臆造寄存器表、命令或成功路径。

区分两类任务：

- 启动已有支持：使用既有驱动与采集模式，通过当前 bringup/采图能力验证。
- 接入未支持相机：在确认电气兼容后，将资料落实为设备树、初始化序列、驱动控制接口及接收模式，
  编译部署并实机诊断。当前平台尚未形成此任务的完整自动化闭环。

音频、相机、屏幕的“快速点亮”是可复用的产品方向；本技能只沉淀相机已验证操作，不推断其他外设已经支持。

## 选择模组和验证素材

优先综合开发者可购买性、现有使用量、接口/电气兼容与实际供货情况；“树莓派常用”是候选筛选线索，
不是与目标板兼容或无需转接的证明。购买前仍核对实物接口、引脚、电压与目标模式。

用户提供的选型线索：Sony/OV 使用广，思特威 SC835HAI 有客户适配经验，IMX415 为 800 万像素级且曾遇 B 端缺货。
这些是团队经验，不是当前库存、供货承诺或平台支持清单；采购或具体适配时再核实。

在目标板上记录素材起点：尚未点亮、已点亮但未做 ISP、已调优。供应商在其他环境点亮过，
不表示目标板已有适配；供应商已经提供完整驱动和效果库时，也不能把复用结果包装成 AI 从零开发。
验证新相机适配应选择确有缺口的组合；验证 ISP 则选择可稳定采集但仍有待改善问题的组合。

## 版本与日志排障

先核对 OS、实际 SDK、驱动/相机包、模组及模式；将文档版本与实际安装版本分开记录。
I²C 有地址仅说明部分控制链路可达，不能证明初始化、MIPI 采图或 ISP 链路正常。

历史线索：团队曾在 IMX415、RDK OS 3.3.3 与 SDK 1.0.17 组合下遇到 I²C 有地址、tuning 无法进入、
demo 无法运行，反馈需等待 3.4.0 的版本能力。复现时核对对应发行说明、实际包及模组条件；
不要据此统一要求升级到 3.4.0，也不要覆盖亚博模组资料中的其他版本要求。

团队曾确认某个标定文件缺失 warning 属日志优化项。只有确认对应版本的默认/回退效果库实际生效，
且出图、控制与相关验收正常时，才把该条日志判为不阻塞；不要忽略所有标定缺失告警。
保留影响复现的日志，将失败定位到版本、驱动、采集或 ISP 的具体阶段。

## ISP 效果与对标案例的证据边界

用户反馈：加入 X5 Tuning guide 后，办公室场景的噪点、雾感与彩噪明显改善；
另以全志“Datasheet 到驱动配置、Agent 从零推进 ISP”作为对标路线。
可据此优先补齐关键资料和端到端能力，但本会话未提供这些案例对应的运行 ID、配置或前后图。
不要把外部案例描述或用户报告升级为当前平台已验证能力。

验收时保存可感知差异和图像证据，例如雾感是否减少、文字边缘是否保留、暗部和彩噪是否下降；
尽量固定场景、光照、焦点与取景。需要隔离 ISP 参数影响且设备支持时，以同一 RAW 回灌做受控比较。
实拍场景变化、人工观察、模型判断与校准指标分开记录；避免靠单一亮度统计或主观描述宣布全面达标。
