# 高可用部署路径

当前默认部署是单活跃 Web + 单 Worker + PostgreSQL，配合异机看门狗、小时级备份和冷恢复。
这保证了可恢复性，但不等于热切换高可用。启用 HA 前必须先完成容量验收和租户/告警语义
的双跑对账。

## 推荐形态

```text
             ┌──────────────┐
             │ 外部探针/入口 │
             └──────┬───────┘
                    │
        ┌───────────┴───────────┐
        │ 负载均衡 / 健康检查     │
        └───────┬────────┬──────┘
                │        │
          d-obs web A  d-obs web B
                │        │
                └────┬───┘
                     │
        PostgreSQL primary → standby
                     │
                 单活跃 worker
```

## 必须满足的条件

- Web 实例无本地状态依赖；session、告警配置、行动队列和遥测控制面都走中心库。
- Worker 通过租约或数据库 advisory lock 保证同一环境只有一个评估者，避免重复通知。
- PostgreSQL 使用流复制、明确 WAL 保留和故障切换演练；备份仍需保留。
- `/status` 纳入外部探针，切换时同时验证 OTLP、状态页、告警写入和设备心跳。
- 发布使用同一 release SHA；先灰度 Web，再切换 Worker，最后执行后置验证。

## 未完成项

本仓库提供恢复脚本和契约，但不替部署方创建第二台机器、负载均衡或数据库集群。生产启用
前请把主机地址、复制槽、RTO/RPO、租约 TTL 和切换负责人写入环境 runbook，并完成一次
真实故障切换。
